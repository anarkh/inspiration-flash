# 《无限流》MVP 第二阶段试玩改进建议

- 日期：2026-07-24
- 分支：`codex/infinite-flow-mvp-iteration-2`
- 基线提交：`df21c71fc056bfa6d4f08f4df402017737f14d01`
- 试玩版本：本地 Vite 开发构建

## 结论

当前版本已经形成可理解、可推进的“主神空间整备 → 副本探索 → 战斗/奖励 → 本局构筑”循环。敌方意图、探索指引、战利品袋、入场快照和刷新恢复是本轮最稳定的体验。

第二阶段不应先扩充更多机制。优先级应为：

1. 修正任务总进度、战术物品可用性和封印名称三类正确性问题。
2. 把“可通关”与“可完成主神指令”拆开，补齐消费和入场前的缺口提示。
3. 重排移动端首屏和主操作位置，以折叠与 `?` 渐进披露复杂机制，而不是删除设计背景。
4. 补齐中文状态、战斗结算、伤害预估、恢复提示等反馈。

## 试玩方法与覆盖

三个 agent 使用相同代码、不同端口的独立实例试玩，避免同源存档互相影响。

| 视角 | 独立实例 | 实际路径 | 覆盖结果 |
| --- | --- | --- | --- |
| 新手玩家 | `5174` | 主神空间 → 妖塔准备 → 2 场战斗 → 2 个奖励节点 → 回响选择 → 隐藏任务 | 袋中 465 点，隐藏任务 1/2；未到首领 |
| 系统/数值玩家 | `5175` | 双功法与补给构筑 → 妖塔首战 → 奖励节点 | 战力 175→235，总承伤 9/20，袋中 235 点；未到首领 |
| 移动端/迁移 | `5176` | 桌面熟悉 → 390×844 入场 → 首战 → 奖励节点 → 刷新恢复 | 无横向溢出；恢复到已清节点且收益保留；未到首领 |

已覆盖：

- 主神空间购买、功法与基础构筑。
- 副本选择、难度、回响、携行快照与多个 `?` 帮助。
- 怪物战斗、敌方意图、普通奖励、回响遗物和隐藏任务。
- 390×844 触屏布局、滚动、弹层、地图与刷新恢复。

未覆盖：

- 首领、出口结算、死亡、撤退和失败重试。
- 第二章至第十九章的实际流程。
- App/小程序真实容器、安全区和系统返回手势。

## 已验证的优势

### 1. 当前动作始终可定位

“战斗指令/探索指引 + 定位”能把玩家带到当前关键操作。回响遗物未选择时，系统会明确说明路线为何暂时封锁。

### 2. 敌方意图支持战术决策

首战能读到撕甲后果和雷火符反制。系统玩家在没有雷火符时使用镇岳、归息和防御，将总承伤控制在 9/20，说明防御与功法不是装饰性按钮。

### 3. 本局与永久成长的边界基本成立

功法、携行、回响等入场快照能被玩家观察到；每门已学功法的战技可在同一场战斗分别使用一次。战利品袋同时展示点数、物品和不同退出方式的保留比例。

### 4. 移动端基础适配和恢复可靠

390×844 下未发现横向溢出，主要按钮触控面积基本足够。刷新后能恢复当前节点、已清节点、袋中收益和最近事件，没有重置本局进度。

## P1：下一迭代必须先处理

### P1-1 主神指令总进度与目标状态不一致

证据：

- 新手实例首次战斗后为 1/3；只领取两个普通奖励节点后变为 3/3，但没有捕获宠物，也没有携带或使用吐纳诀。
- 系统实例入场时“承伤 ≤20”和“吐纳诀”已显示满足，总进度仍为 0/3；首战后为 1/3，奖励节点后为 2/3。

风险：玩家会误判目标已完成，且主神指令失去可信度。

最小方案：

- 总进度只从三个目标的规范化状态派生，奖励节点不得直接递增。
- 把可能反转的条件标记为“当前满足”，出口结算时才转为“已锁定完成”。
- 增加回归测试：普通奖励结算不改变捕获、功法和承伤目标的完成数。

验收：

- 未捕获宠物、未满足功法条件时，总进度不能达到 3/3。
- 刷新后总进度与三个条目状态一致。

### P1-2 背包、战利品袋与战术携行的可用性表达错误

证据：

- 购买护甲补片后，副本门仍提示缺少；入场快照为 x0，关键“装入携行”步骤藏在折叠内容中。
- 副本内获得雷火符后，战斗按钮显示“雷火符 x1”且可点击；点击后日志才说明“未装入战术携行，当前无法使用”。
- 敌方意图仍推荐当前不可用的雷火符。

风险：资源被无效消费；按钮和推荐会诱导玩家执行必然失败的操作。

最小方案：

- 所有物品统一显示“背包/袋中数量”和“本轮战术可用量”。
- 不可用物品按钮禁用，文案显示“袋中 1 / 战术可用 0”。
- 敌方推荐基于战术可用量生成；不可用时推荐防御或其他真实可执行动作。
- 入场确认列出“已购买但未装入”的物品，并提供一键装入/替换。

验收：

- 副本内拾取但未装入的道具不能显示为可执行战术。
- 所有敌方推荐都能在当前回合直接执行。

### P1-3 “下一推荐”混淆通关能力与任务完成能力

证据：

- 妖塔显示“战力充足 / 下一推荐”，但新手入场即缺缚灵网、吐纳诀，无法完成两个主神指令。
- 系统玩家购买双功法与护甲后只剩 50 点，已无法购买 210 点缚灵网，捕获目标在本局开始前就被锁死。

最小方案：

- 拆成“通关准备”和“主神指令准备”两个状态。
- 显示缺口及直达入口，例如“去补给商人”“去功法大师”“装入携行”。
- 消费后若余额低于当前指令的最低必要资源，提示影响但不硬拦截。

验收：

- 玩家在点击入场前能判断哪些目标可完成、哪些目标已放弃。

### P1-4 移动端关键操作被超长内容埋没

证据：

- 390×844 下副本门把 19 章全部单列展开，滚动容器约 26,175px；首章“准备进入”约在 y=1165。
- 入场后的页面约 4,548px，首次“进入战斗”约在 y=4147。

最小方案：

- 副本门默认只展开“下一推荐”，其他章节显示单行摘要，点开进入详情抽屉。
- 准备页固定底部“进入”操作。
- 局内首屏只保留当前节点、推荐动作、生命和战利品摘要；快照与规则放入可折叠的“本局详情”。
- 不删除规则文本，折叠内容继续由稳定 `?` 帮助项承载。

验收：

- 390×844 下从打开副本门到“准备进入”不超过一次短滚动。
- 进入副本后，当前主操作在首屏或固定操作区可见。

### P1-5 “首领路线封印”与“出口封印”语义冲突

证据：

- `?` 将“首领封印”解释为通往首领路线的前置条件，并说明 0/1→1/1 不会立即开战。
- 卡片正文又使用“击败首领，解除出口封印”，两者因果与计数对象不同。

最小方案：

- 拆成“首领路线封印”和“出口封印”两个稳定 help id。
- 当前计数如果代表击败首领，应命名为“出口封印”；如果代表路线前置，则保留“首领路线封印”并改正文。

验收：

- 名称、计数、正文、`summary/mechanic/guidance/readout` 指向同一个规则对象。

## P2：完成正确性修复后处理

### P2-1 首局信息密度过高

入场前后同时展示侵蚀、追兵、小队、功法、携行、铭刻、器魂、回响、场域法则、法则区段、封印和战利品袋。

建议：首局默认展开“任务、当前节点、生命、战利品、当前生效法则”；其他内容保持摘要 + `?`。这是渐进披露，不是删除机制。

### P2-2 路线选择缺少可区分信息

首战后多个可选项均叫“相邻未知区域，可探索”，可访问名称和视觉信息都相同；寻路构筑也没有提供方向价值。

建议：

- 可选节点补充“左上/正上/右上”等方向名。
- 未邻接迷雾格不使用大量同名禁用按钮。
- 寻路或高感知仅揭示一位信息，例如“偏奖励/偏危险/地标气息”，继续保留迷雾决策。

### P2-3 中文状态不完整

目标状态混有 `damage taken`、`Pet not captured`、`Method missing`。

建议：统一映射为“承伤 15/20”“未捕获”“未携带吐纳诀”；英文诊断仅保留在开发模式。

### P2-4 战斗数值反馈不足

攻击按钮显示 22，实际伤害为 21，但敌方防御和计算过程不可见，玩家难以比较攻击与功法。

建议：按钮显示“预计造成 21 / 预计承伤 3”，完整公式保留在 `?`。战斗胜利后增加紧凑小结：承伤、奖励、目标变化和下一步。

### P2-5 移动端帮助触控目标偏小

`?` 视觉尺寸约 28×28，同页可连续出现 14 个。

建议：视觉圆点不变，将透明点击区扩至至少 44×44，并增加相邻帮助入口的间距。

### P2-6 恢复成功但缺少明确确认

刷新能正确恢复节点和收益，但只能通过页面状态推断。

建议：恢复后显示一次轻提示，例如“已恢复：妖塔一层 · 断符石盘；袋中 235 点”。App/小程序应按逻辑节点恢复，不依赖浏览器滚动位置。

## P3：文案与精修

- “呼吸 +1”与日志“蓄息 +1/2”统一术语，并显示常驻计量。
- “缝生线：领取奖励节点后回复 12 生命”改为“选择后，后续每次领取奖励节点回复 12 生命”。
- 撤退按钮直接预览当前实际带回数值、物品取整和装备损失，而不只显示比例。
- 移动端地图为小程序字体缩放和安全区预留余量：节点最短边至少 48px；必要时使用 4 列或可横移地图。

## `?` 帮助必须保留的设计语义

界面可以折叠、换层级或为移动端改成底部说明层，但以下背景不能为了缩短页面而删除：

- 难度只改变本轮敌人、陷阱和收益，不改变剧情路线；入场后冻结。
- 回响仅本局生效；流派、遗物、归档种子与永久成长的边界。
- 功法、小队、血统、携行、铭刻、器魂等入场快照为何不会被局中主神空间状态回填。
- 每门已学功法的战技每场可分别使用一次；常用功法只影响排序。
- 战术携行与战利品袋是两套库存；副本内拾取不等于本轮战斗可用。
- 场域法则、雾压、侵蚀段位、追兵和法则区段的实际结算规则。
- 战利品通关 100%、撤退 50%、濒死 20% 的带回比例与装备遗失规则。
- 隐藏任务无需预选、失败不阻断主线，但奖励要求成功撤离。
- 迷雾的信息隐藏是有意的路线决策，不是加载失败。
- 首领路线封印与出口封印是两个不同规则对象。
- 旧档兼容背景继续保留在稳定 help id 中，不从过期界面反推规则。

`src/dungeon-feature-help.ts` 应继续作为跨 Web、App 和小程序的版本化单一资料源。信息架构改造只替换呈现层，不改写或丢弃这些规则语义。

## 两轮“试玩 → 反馈 → 修复”闭环

在以上首轮建议形成后，又由新手、系统/数值、移动端/迁移三个视角连续执行了两轮独立试玩。每名试玩者使用独立 origin 和端口，不共享存档；子 agent 未修改代码，服务均在结束后停止。

### 第一轮闭环

| 视角 | 实际覆盖 | 收敛反馈 | 已实施修复 |
| --- | --- | --- | --- |
| 新手 | 购买缚灵网、学习吐纳诀、手动调整携行、首战捕获 | 零库存默认预设占满 3 个槽；捕获后缺少最近进展；商店按钮重名；隐藏兼容目录污染无障碍树 | 自动携行先移除零库存预设并优先装入指令道具；捕获加入最近进展；商店按钮使用物品名与价格；主界面不再渲染隐藏商店/副本目录 |
| 系统/数值 | 吐纳诀、缚灵网、护甲补片、战斗、事件、撤退 | 章节侦察在撤退后丢失；攻击/功法无法判断捕获线与击杀；撤退只预览袋内收益；意图推荐不可用雷火符 | 新增持久 `enteredDungeonIds`；基础动作显示预计伤害、剩余血量、行动后可捕获或将击杀；撤退显示评分奖励与总入账；不可用反制降级为建议防御 |

浏览器回归另发现撤退预估误用“全图潜在奖励”作为基础值，已改为与实际出口结算相同的奖励基数。首战捕获路径的预估 `28 + 37 = 65` 与账户实际 `340 → 405` 一致。

### 第二轮复测

第二轮在修复版上重新建档验证，三方均报告：

- P0：0。
- 第一轮的自动携行、伤害/捕获预览、意图降级、捕获摘要、撤退后侦察任务、战斗首屏、44px 触控目标和详情语义均已通过。
- 390×844 下捕获约位于 y=555，攻击约 y=624，功法约 y=639，防御约 y=747；前三个基础动作完整进入首屏。
- 战斗高级详情仍保留难度、侵蚀、追兵、小队、功法、携行、回响和场域法则等 `?` 说明。

第二轮新发现并修复：

1. **带伤再次入场、零节点撤退出现四套数值。** 原因是预览按当前生命差计算，真实结算按本局 `damageTaken` 计算。现在预览、标题、明细、账户入账与日志共用 `getRunEconomyPreview`；实测均为评分 190、倍率 0.27、奖励 37，账户 `405 → 442`。
2. **撤退页把普通难度写成“挑战完成”并显示材料 `+1`。** 现在明确显示“本轮已结束（未通关）”，难度材料为 `+0`。
3. **玩家日志暴露 `retreat`、`disabled/retreat` 等内部枚举。** 新结算日志改为“主动撤退”“本轮追兵未启用”“奖励倍率 0.27”；结构化 `lastOutcome` 继续保留内部字段供存档与解析使用。
4. **副本详情展开后名称仍为“展开”。** 现在按状态切换“展开/收起”，同时同步 `aria-expanded`。
5. **关闭状态下残留孤立 `×`。** 帮助关闭图标改为无文本 CSS 图形，隐藏弹层增加 `aria-hidden/inert`；复测无障碍树不再出现孤立关闭符。

移动端试玩提到的“路线推演与补强”折叠摘要没有移除：它是刻意保留的渐进披露入口，不是旧版隐藏兼容目录。关闭时只暴露摘要，复杂路线设计仍可由玩家主动展开，符合未来 App/小程序迁移时保留机制语义的要求。

## 最终验收口径

- 新手从新档可通过“购买缚灵网 → 学习吐纳诀 → 一键装入 → 首战两次攻击 → 捕获 → 撤退”完成完整可解释路径。
- 攻击/功法预估不得读取旧战斗日志；击杀时仍准确显示剩余 0。
- 撤退预估必须与真实结算使用同一结果对象，既有伤势不能算作本局承伤。
- 撤退和失败不得显示通关或难度材料到账。
- 复杂机制可以折叠，但 `?` 帮助与详情中的设计语义不得删除。

## 新增五轮“试玩 → 反馈 → 修复”闭环

在前述两轮之后，又连续完成五轮独立试玩。每轮固定同一份源码快照，由新手、系统/数值、移动端/迁移三个视角分别使用独立端口和全新存档；子 agent 只试玩和报告，不修改文件。五轮端口依次为 `5191–5193`、`5201–5203`、`5211–5213`、`5221–5223`、`5231–5233`，所有服务均在当轮结束后停止。

- 修复为零清理节点不产生评分奖励；濒死回城恢复 20% 生命，0 生命状态禁止入场。
