# 横版清关 · 动作战斗原型 v1

把回合制战斗改成**横版清关**（带纵深走位带的清版动作）之前，先用这个隔离原型验证手感和规则。
不读游戏状态、不写存档、不调用正式命令；数值只用于试手感，正式接入时以领域层为准。

## 打开方式

从 `infinite-flow-wechat/` 启动静态服务（例如 `python3 -m http.server 8762`），打开：

`http://127.0.0.1:8762/prototype/action-combat-v1/`

无依赖、无构建：纯 HTML + CSS + ES 模块 + Canvas 2D。桌面浏览器里显示为居中的手机框；手机（窗口宽度 ≤ 600）直接铺满，
HUD 和按键会避开刘海与底部横条（`env(safe-area-inset-*)`）。切到别的标签页时战斗暂停，回来后不补帧。

## URL 参数

| 参数 | 作用 |
| --- | --- |
| `?controls=onehand\|dual` | 操作方案。`onehand` 单手（一个浮动摇杆 + 站定自动连斩 + 三个边缘按键，**默认**）；`dual` 双手（左摇杆 + 右侧按键）。见「操作」 |
| `?hero=action\|standin` | 主角美术。`action` 新画的动作图集 `assets/hero-action/`（默认）；`standin` 用旧行走图拼出的替身图集（只为在没有动作图时也能调动画管线）。见「主角动画」 |
| `?viewport=auto\|390x844\|320x568` | 视口。`auto` 适应窗口（默认）；另两档在桌面上模拟这两种手机 |
| `?slowmo` | 模拟按 1/4 速度运行，便于逐帧看动作与特效 |
| `?debug` | 画判定框：受击框（青）、攻击框（金 / 红）、预警形状、敌人站位目标，以及状态、攻击冷却、帧号、顿帧，还会描出触控热区 |
| `?shot` | 隐藏顶部演示栏，便于截图 |
| `?seed=N` | 随机种子（默认 1）。种子和输入都相同时，整场战斗完全一样 |
| `?safe=上,下` | 模拟安全区（CSS px），例如 `?safe=47,34` 模拟带刘海和底部横条的 390×844；桌面浏览器里 `env()` 恒为 0，只能这样看效果 |

顶部演示栏可以切操作方案、视口、慢放、判定框，也能重开。切换会写回 URL（`history.replaceState`），刷新后保持；
切操作方案会立即换按键并重开本局（两种方案传给模拟层的出招辅助倍率不同：双手 `assist: 1`，单手 `assist: 2`）。

## 操作

- **键盘**（始终可用，和触屏同时生效）：WASD / 方向键移动（8 方向），J 攻击，K 闪避，L 战技，U 法术，I 道具；
  战意满时**按住 J 0.3 秒**也放战技（短按仍是攻击）。
- 按键图标都取自游戏的水墨战斗按钮条（攻击 = 剑，闪避暂用盾，法术、道具同游戏），没有底板，浅色水墨直接压在暗色地面上。
  可见图标小、触控热区更大（圆形，互不重叠），图标下方有一行小字说明。摇杆和每个按键各自追踪自己的 Pointer，可以一边推摇杆一边按键。
  页面设了 `touch-action: none`，不会滚动或缩放。
- **共同的按键状态**：攻击 / 战技键上的三颗战意珠按真实战意点亮（和游戏一样用亮珠 / 暗珠盖住图上画的三颗）；战意满时攻击 / 战技键外圈有一圈白色水墨光晕呼吸。
  闪避、法术、道具冷却时变灰并有扇形倒计时；战意不足 1 时法术变暗；道具右上角显示丹药数，用完变暗。
  模拟层拒绝的按键（`denied`）会让对应按钮轻轻一抖，并在操作区上方提示原因（战意不足 / 法术调息中 / 生命已满 / 丹药已用完…）。
- **双手方案**（`dual`）：左半屏任意处按下，摇杆出现在按下的位置（浮动摇杆），拖出外圈时底盘跟着走，360° 模拟量，中心 18% 是死区。
  右下角是大的攻击键，闪避、法术、道具在它左上方排成一段弧（从下到上：闪避、法术、道具），右手拇指以攻击键为圆心就能扫到。
  战意满时攻击键下方的小字变成「长按 · 战技」：**短按 = 攻击**（松手时出招），**按住 0.3 秒 = 战技**（按住期间外圈有一圈进度）。战意不满时按下立即攻击，没有额外延迟。
- **单手方案**（`onehand`，默认）：屏幕下方约 60% 的任意位置（按键除外）按下都会出现浮动摇杆。
  - **站定自动连斩**：摇杆回中或松手时，只要有活着、可被打到的敌人在攻击距离内（受击框边缘距脚点 x ≤ 84、z ≤ 26，身前身后都算），就每 0.1 秒补一次攻击键，
    打出有节奏的三连斩：一段、二段紧接，第三段先跃起蓄势再劈下（重击的那一拍），之后重新起一串。附近没有敌人就什么都不做。
    **一推摇杆就走**：站定时补的攻击键会在推摇杆时作废，收招阶段推摇杆立即转入跑动（一、二段收招 0.06 秒后、第三段 0.15 秒后），不会被排队的下一刀拖住。
    刚按下的 0.12 秒不算站定，所以甩动的开头不会误出刀。判断逻辑是 `src/input/logic.js` 里的纯函数 `wantsAutoAttack()`。
  - **甩动闪避**：摇杆推过半径 70% 后 180 毫秒内松手 = 朝甩的方向闪避（推着走了很久再松手不算；先回中再甩也算）。
  - **双击闪避**：两次快速轻点（每次 ≤ 0.2 秒、几乎不动、间隔 ≤ 0.26 秒）= 朝背后闪避（后撤）。
  - 右下角三个按键：**战技**（攻击图标，只有战意满时才亮，点一下就放）、左边**法术**、上面**道具**。都在屏幕边缘，拇指不用离开下半屏。
  - 首次触摸前，摇杆下方有一行操作提示，摸过后淡出。
- **按键尺寸**（逻辑 px，390 宽；320×568 档整体再乘 0.82 换成屏幕 px）：

  | 方案 / 视口 | 可见直径 / 触控直径 | 位置（中心） |
  | --- | --- | --- |
  | 双手 390×844 | 攻击 86 / 108，其余 54 / 74 | 攻击 (331, 781)；闪避、法术、道具在以攻击为圆心、半径 92 的弧上（仰角 −10°、38°、86°） |
  | 双手 320×568（逻辑高 692） | 攻击 76 / 96，其余 46 / 66 | 攻击 (338, 636)；弧半径 82 |
  | 单手 390×844 | 战技 62 / 84，法术、道具 48 / 68 | 战技 (345, 791)，法术 (269, 798)，道具 (348, 715)；摇杆区 y ≥ 338 |
  | 单手 320×568 | 战技 56 / 76，法术、道具 44 / 62 | 战技 (350, 644)，法术 (280, 650)，道具 (352, 574)；摇杆区 y ≥ 277 |

  操作区放不下宽松档时（例如 390×844 加 34 的底部横条）自动用紧凑档；再放不下就整体等比缩小。所有按键都在纵深带下沿以下，不压战斗区域；
  布局是 `logic.js` 里的纯函数 `dualLayout()` / `onehandLayout()`，`tests/input.test.mjs` 检查两档视口（含安全区）下不重叠、不进纵深带、不出屏。

## HUD

和游戏战斗界面同一套视觉（暗色底框 + 金色描边）：

- 左上：头像、名字、「生命 当前/上限」和细血条；掉血时白色残影先停 0.45 秒再缩回，回血时血条亮一下绿光。低于 30% 血条变红，屏幕边缘出现呼吸的红色暗角。
- 右上：「◆ 第 N/3 波 · 剩余 K」，清波后显示「已清」。
- 首领在场时顶部出现首领条：◆ 名字、生命数值、红色血条（带白色残影）和更细的韧性条；破绽时标签「破绽」闪烁、韧性条变亮白，暴怒时标签「狂暴」、血条更红。
- 右侧连击数：2 连击起出现，每次命中跳一下，快断时变淡，断了淡出。
- 清波后右侧边缘出现呼吸的「前进 ▶」（`world.advance`），每次 `go` 事件会快速闪几下。
- 横幅（深色横条 + 金色细线，同游戏「第 N 回合」）：每波开始「第 N / 3 波」、首领登场「◆ 名字 · 首领」（暗红底）、清波「清 场 · 向右前进」、暴怒、通关、倒下。
- 见切慢放期间屏幕边缘有一圈淡淡的冷色光（见切文字由特效层画）。
- 结算面板：胜利 / 倒下、用时、受击次数、最大连击，以及剩余生命（胜）或止步波次（败），「再来一次」重开。320×568 下仍清晰可读。

## 表现与特效

主角用新画的动作帧（见「主角动画」）；敌人仍是一张插画加程序化动作。没有特效贴图。代码在 `src/view/renderer.js`（绘制与镜头）、
`sprites.js`（姿态与绘制）、`hero-anim.js`（主角动作帧）、`vfx.js`（事件特效）。

- **打击感**：命中点局部闪光，沿受击方向的十字光芒和火花，一道斜切的亮痕（角度随段数变）。三段刀光沿着剑走（见「主角动画 · 刀光」）：
  一段水平横扫，二段斜向上挑，三段过头劈下，落点（剑尖触地处）裂地、扬尘、地面冲击环。
  受击者先闪白（按画面时间亮两帧后迅速褪去，顿帧期间也会褪，并在顿帧里抖动），然后后仰硬直。顿帧冻结全场，特效照常播放。
  震屏按创伤值累加（封顶 9 px），同一帧打中几个敌人只算最重的一次。重击另有轻微的镜头推近和极淡的全屏亮闪（不超过 9%），不再整屏发黄。
- **伤害数字**：按目标分列。同一目标的新数字出现在原位，旧数字上移一格并提前淡出；几个目标挨得近时各列左右错开，不会叠在一起。数字在头顶血条上方。
  普通 20 px、重击 / 击杀 30 px，都是金色；主角掉血红色，回血绿色「+N」。
- **击杀**：爆成墨、雾或烟加火星，尸体从头往下锯齿状溶解：雾中妖鬼化雾，跳火小鬼化火星和烟，剔骨塔卒化墨。首领死亡另有更大的金色冲击。
- **主角**：见「主角动画」。道具时泛绿光；法术有青色描边和脚下符阵；战技蓄力时金色描边渐亮，冲斩和横扫时满亮。
- **敌人姿态**：雾中妖鬼浮空飘动，脚下雾气缭绕；跳火小鬼蹦跳，头顶冒火星；剔骨塔卒沉重踏步。
  蓄力时后仰、变大、颤抖，红色外发光随预警进度增强（蓄力重击更强）。出手时前扑；扑击和冲锋是拉长的冲刺姿势，吐火是后坐。另有后跳、受击后仰、击飞时按高度后倒、起身。
  首领破绽时前倾垂头摇晃，泛金色外发光，头顶有金光环绕和「破绽」二字；暴怒时泛红色外发光。
- **预警**：椭圆或矩形，填充随进度生长，最后 22% 频闪。矩形（扑击、冲锋、火星）画成圆角长条，带朝攻击方向滚动的箭头。
  蓄力重击用品红色，加斜纹、双层描边和更大的脉动，还有一圈圈从地面升起的环，提示这是见切时机。
- **战技**：起手时金光向主角汇聚，场景压暗（光源处留亮）；判定时出三层宽刀光、横贯的刀芒、双层地面冲击环和速度线，强震屏并推近。
- **见切**：白、青双环（重击为金色）、速度线和地面环；场景短暂去色并偏冷；主角头顶出「见切 · 完美闪避」。慢放由主循环负责。战意增加时，金色光点飞入主角。
- **其他事件**：法术的符阵与出手光；飞行道具画成发光球，带拖尾、火星和地面阴影，消失时爆开；回血的绿色光点；破绽、暴怒、首领登场（扬尘、裂地、压暗）；清场的金色光点；倒下时画面逐渐去色并出现红色暗角。不认识的事件一律忽略。
- **镜头**：跟随主角，按朝向和跑速前探，带平滑。附近有敌人时向敌群偏移，但主角离屏幕边始终不少于 80 px。
  锁场（`world.arena`）时平滑收进场地边界，`world.advance` 为真或解锁后平滑放开。屏幕外的敌人在屏幕边缘显示小箭头，蓄力时变红并闪烁。
- **场景**：手绘横版场景图 `assets/stage-demon-tower.jpg`。地面线在图高 59.6% 处（`floorFraction: 0.404`），对齐到纵深带上沿再往上 34 px，所以站在纵深最远处的角色也踩在地面上，不会站到墙上。
  图片下沿以下用底边的镜像续接到控制区。另有缓慢漂移的雾带、两道淡光柱、前后两层视差的上升火星、前景雾和暗角；纵深越远的角色越暗。
  旧背景（低清全景加平铺地面）那一行保留为注释，换回去时自动启用接缝雾、接触阴影和地面羽化。
- **性能**：粒子用对象池（上限 520 个，发射时不分配内存），形状上限 64，数字上限 18。着色剪影（闪白、外发光、残影、压暗）在加载时按半分辨率缓存一次；
  墙、地面、雾、光柱、暗角在尺寸变化时缓存。描边发光用「宽淡线 + 细亮线」代替 `shadowBlur`，只有角色外发光用 `shadowBlur`。画布像素比上限 2。
  在无头 Chrome（软件光栅、像素比 2）里，空闲帧约 12 ms，战技加重击的峰值帧约 17 ms（都含 DOM HUD）。`?debug` 时左上角另外显示当前粒子数和形状数。

## 主角动画

主角是一套新画的侧面动作帧（`assets/hero-action/hero-action.png` + `hero-action.json`，1973×1650，33 个帧条目（跑步 8 帧共用 4 张图）、12 个动作，全部朝右，站姿高 `unitHeight` 320 px 对应 `hero.height` 128）。
`src/view/hero-anim.js` 校验图集、按模拟状态挑帧（纯函数 `heroBeat()`，只看 `state`、`stateTime`、`stride`、`y`、`vx` / `vy` / `vz`、`slide`，空闲呼吸另看画面时钟），
`sprites.js` 负责绘制和其上一层很轻的程序化动作。图集缺失或不合规时，页面整屏显示红色错误（缺哪个动作、哪一帧、哪个字段），不会悄悄换成别的图。

| 动作 | 帧（按顺序） | 何时显示 |
| --- | --- | --- |
| idle | 吸气、呼气 | 站立；每帧 0.9 秒，后 45% 交叉淡入下一帧 |
| run | 8 帧：落地、下沉、交叉、腾空，重复一遍（`run_4`–`run_7` 与 `run_0`–`run_3` 是同一组图：上身完全一致，只有腿在动） | 按**走过的距离**换帧，见下面「跑步」 |
| attack1 | 起手（剑收在身后）、平斩、收势 | 起手 0.09 秒 → 判定 0.07 秒 → 收招 0.22 秒 |
| attack2 | 起手（剑压低）、斜上挑、收势（剑举过头） | 起手 0.08 → 判定 0.07 → 收招 0.24；收势正好接第三段的举剑 |
| attack3 | 举剑蓄势、跃起最高点、蹲身下劈（剑尖触地）、收势 | 起手 0.22 秒（前 40% 蓄势，后 60% 在空中）→ 判定 0.09 → 收招 0.32（前 40% 停在下劈姿势上） |
| skill（战技） | 蓄力下蹲、低身冲斩、大横扫、收势 | 起手 0.2 → 判定 0.14（前 45% 冲、后 55% 扫）→ 收招 0.4（前 30% 仍是横扫） |
| spell（术法） | 结印、推掌 | 施法 0.18 秒结印，光弹从推掌的掌心（身前 54 px、高 0.68 倍身高）飞出 |
| item（止血丹） | 举丹、服下 | 服用 0.4 秒的前 45% / 后 55% |
| dodge | 起步、贴地滑翔 | 前 25% 起步，其余滑翔；闪避结束后的滑行收势仍用起步帧 |
| hurt / down / getup | 受击后仰 / 倒地 / 单膝起身 | 受击；被击飞上升时用受击帧、下落和躺地用倒地帧；倒地最后 0.3 秒单膝起身 |

**程序化的一层**（轻量，只在姿势本身没画出来的地方补）：

- 出招落定的一刻（平斩、上挑、下劈、横扫）身体轻压一下再弹回（0.1 秒，第三段最重）；按模拟时间算，顿帧时就停在压扁的那一帧上，同时有很轻的抖动。
- 落地（击飞落地、单膝起身、闪避滑停）轻压一下。
- 跑动时只在加速时再前倾一点、减速时后仰一点（最多约 1.4°，画面本身已经前倾）；跑着停下会往后晃一下再站稳。
- **转身**不是一帧镜像：约 0.07 秒里身体压窄到侧面、换向、再展开。
- 换帧时，旧帧在新帧后面留 0.05–0.08 秒的残影（快动作像拖影，收势时像淡出）；起手、蓄势、受击、跑步帧直接切。
- 闪避、第三段、战技留下的金色残影用的就是当时那一帧；跃起那一帧地面影子缩小（跃起已经画在帧里，模拟层的高度不变）。
- 旧的整体扭曲（大幅前倾、拉伸）都去掉了，避免画好的动作被拉变形。

**跑步**：

- 步频：图集给出 `runCycle: 496`（320 比例下，8 帧一圈时着地脚正好不动所走的距离，换到 128 px 身高是每圈 198 px）。
  按这个值脚完全锁定，但原来 210 px/s 的跑速只有约 8.5 帧 / 秒、每秒 2.1 步，看起来像慢跑。
  现在跑速提到 240 px/s（纵深 170），步频系数 `RUN_TUNING.cadence = 1.15`：每圈 172.5 px，约 11.1 帧 / 秒、每秒 2.8 步，着地脚每步往后滑约 13%（约 10 px）。
  选它是因为：任何步频下，同一帧停留期间着地脚都会跟着身体前移一帧的距离（约 20–25 px），这个才是主要的“滑”；帧率高，这段滑就短、动作就顺。
  在原速度上硬提步频（210 px/s、11 帧 / 秒）步子太碎、滑 23%；只提速度到全锁定需要约 280 px/s，改动玩法太多。
- 起跑：模拟层在进入跑动时把 `stride` 清零，所以每次都从「落地」帧开始；换帧按距离，加速的那几帧自然停留更久，步频随速度渐起。
- 停下：松开摇杆后速度在约 4 帧内刹停，期间显示「下沉」帧（重心压低的刹步），然后交叉淡入站姿，并有一次很轻的后仰回正。
- 起伏：原画的头部起伏约 30 px（游戏里约 12 px）。只把两张腾空帧（交叉、腾空）往下压 45% 的超出量（最多约 3 px），
  落地和下沉帧的着地脚保持贴地、不抬高（抬高会让脚离开影子）。影子始终画在地面上不动。
- 转身：跑动中反向时，身体在约 0.07 秒里压窄到侧面再展开，循环不中断（反向减速时换帧变慢，再随速度恢复）。

**刀光**：每段刀光是一段椭圆弧，圆心在持剑肩（每个动作一个固定点），半径是打击帧剑尖到肩的距离，所以弧一定经过打击帧的剑尖（`tip`）。
弧从起手帧的剑尖方向出发，到打击帧剑尖，再朝收势帧的剑尖方向延伸（收势往回收时只多走 0.45 弧度）。图集只在打击帧标了 `tip`，
起手和收势帧的剑尖是在 `hero-action.png` 上量的，写在 `hero-anim.js` 的 `ARC_POSES` 里。横斩（一段、战技）压扁成 0.26 / 0.3 的扁椭圆，并固定从身前（下侧）扫过；
第三段的地裂落在下劈帧的剑尖处。刀光出现时已经扫到打击帧剑尖，随后在收势时间里继续前扫、尾部追上并淡出，并跟着主角的前冲移动。

**替身图集**：`?hero=standin` 用旧行走图的四帧加上旋转、缩放和编出来的剑尖拼成同一套动作，供没有动作图时调试管线；`HERO_ART_DEFAULT` 决定默认用哪套。

## 规则（真实可玩的部分）

- **移动**：在纵深带内 8 方向移动，左右朝向跟随摇杆，跑速 240 px/s（纵深 170）。速度有加减速：约 6 帧加到全速、4–5 帧刹停，掉头约 8 帧从全速反向到全速。
  镜头横向跟随主角，朝向前方略微前探。舞台长 2000。
  主角和敌人之间有软碰撞：互相挤开，但敌人让路（主角只承受 15% 的推力，对首领 30%），所以总能从空隙里走过去，不会被堵死在角落。闪避和战技期间不参与碰撞。
- **三段连击**：按攻击出第一段；出招期间再按会进入缓冲（0.25 秒），进入收招 0.05 / 0.06 秒后（收势姿势露一下）自动接下一段。
  每段向前冲一步（一、二段 18 px，第三段 34 px），冲步从打击帧前 0.03 秒开始、0.09 秒内缓出，第三段的冲步贯穿跃起。
  第三段是重击：顿帧更长、击退更远，并把敌人打倒在地。收招阶段可以用闪避、战技、法术、道具立即取消；**推摇杆**在收招 0.06 秒（第三段 0.15 秒、战技 0.24 秒、法术出手后 0.1 秒）后取消。
  摇杆回中时按下、还在排队的攻击，在推摇杆时作废（单手方案的自动攻击就是这样按的）；推着摇杆按的攻击照常接下一段。
- **出招辅助**：摇杆基本没推（< 0.2）时出招，自动转向身前身后 170 px、纵深 70 px 内最近的敌人，并在起手阶段向它所在的纵深滑动最多 18 px。
  推着摇杆时以摇杆为准。强度可按世界参数 `config.assist` 整体放大（单手方案会传更大的值）。
- **闪避**：朝摇杆方向冲刺（不推摇杆就朝面向方向），带无敌帧和冷却。起步最快（约 1500 px/s），缓出到 170 px/s，然后有约 0.1 秒的滑行收势（此时已经可以出招）。
  无敌帧内即使身体还在敌人的攻击范围里，这一击也会整段落空，并飘出「闪避」。受击硬直 0.15 秒后，缓冲中的闪避可以打断硬直（倒地不行）。
- **见切（完美闪避）**：闪避开始后 0.18 秒内，若有敌人的攻击判定覆盖主角，或覆盖他起闪时站的位置（也就是不闪就会挨打），
  这一击被吞掉，并触发见切：普通攻击 +1 战意，**蓄力重击 +2 战意**，全场慢放 0.45 秒（`world.slowMo`），之后 1.6 秒内主角伤害 ×1.3。每次闪避最多触发一次。
- **战意 0–3**（对应真实规则 `combat-focus.ts`）：第三段命中 +1（一次重击只算一次，打中几个敌人都一样）；见切 +1 / +2；**被蓄力重击打中 −1**。
- **战技**（满 3 战意，全部消耗）：向前大范围横扫（身后 26 px 到身前 170 px、纵深 ±58），伤害 120（第三段的 3 倍），整招无敌，击倒，削韧 90。战意不满时按键无效并提示。
- **法术「术法」**（耗 1 战意，冷却 5 秒）：沿面向、在主角所在纵深飞出的光弹，射程 440、速度 460 px/s，穿透，每个敌人 34 伤害并打断普通敌人。战意不足或冷却中按键无效并提示。
- **道具「止血丹」**（2 颗）：0.4 秒服用动作（期间可被打断，打断不消耗丹药），结束时回复 30% 最大生命，与其他道具共用 1.5 秒冷却。满血时不能吃。
- **连击数**：每次命中 +1，最后一次命中后 2 秒没有新的命中、或主角被打中，归零（`world.combo`）。
- **雾中妖鬼（近战）**：先走到主角周围的站位上。两个前排站位才能出爪，其余是等候位；等候中的妖鬼若这次打算**扑击**，会对齐主角所在纵深，从远处沿直线扑过来（矩形预警）。
  出手前地面亮起预警，蓄力时长随机（0.42–0.72 秒），敌人后仰、泛红；蓄力结束后，在**预警范围**内出爪 / 扑击。
  同时最多两个近战敌人（含首领）出手，相邻两次出手至少间隔 0.3 秒。
  普通一击能打断它；但蓄力过了 55% 就**收不住了**，只有战技还能打断。第三段把它打倒，倒地和起身期间不吃伤害。
  **硬直抗性**：连续吃了 3 次硬直（1.2 秒内没再挨打就重新计数）之后，下一击不再硬直，它会后跳脱身并马上反击（多半是扑击）。
- **跳火小鬼（远程，形象借自「星坠矿井」章节，见「素材」）**：在主角同侧保持 200–270 px 距离，慢慢对齐主角的纵深，蓄力 0.7 秒（沿纵深的矩形预警）后吐出一颗慢速火星（200 px/s，比主角走得慢），
  走出这条纵深或闪避都能躲开。主角贴近到 125 px 内会后退；退到场地边上就往纵深两侧溜，并在对齐时快速吐一发（蓄力 0.45 秒）。同时最多一只小鬼瞄准。
- **剔骨塔卒（首领）**：韧性 120，韧性大于 0 时挨打不硬直；挨打削韧（第三段、战技、法术削得多），1.5 秒没挨打后每秒恢复 18。
  韧性归零 → **破绽** 2.5 秒（吃 +50% 伤害），然后韧性回满。**生命高于一半时防御更高**：受到的伤害 ×0.65；降到一半时**暴怒**（移动 ×1.25、蓄力和收招 ×0.8、出手间隔 ×0.7）。
  招式由带种子的随机数挑选：① 2–3 连挥（每挥一个椭圆预警，连挥之间会朝主角跟进一步）；② 每第三套（第 2、5、8 套）是**蓄力重击**：1.1 秒的大椭圆预警，
  重伤 + 击倒——这就是留给见切的时机；重击后它会后跳拉开，然后③ 对齐纵深后**冲锋**（矩形预警，沿纵深冲 360 px，击倒）。主角离得远时也会直接冲锋。
- **三波**：第一波 3 只雾中妖鬼；第二波 2 只妖鬼 + 2 只小鬼（第二只晚 3 秒）；第三波剔骨塔卒 + 1 只妖鬼（晚 1.5 秒）+ 1 只小鬼（晚 16 秒）。
  每波开始时锁定一块 600 px 宽的场地（`world.arena`），主角和敌人都出不去；场外的敌人从场地边缘走进来。清完一波解锁，显示「前进」（`world.advance`），
  走到下一波的触发线才开始下一波。三波全清为胜；主角 HP 归零为败。结算面板见「HUD」，「再来一次」重开。
- **反馈**：顿帧（轻 0.06 秒、重击 0.11 秒，冻结全场，特效照常播放）、震屏、击退、受击闪白、伤害数字、刀光、敌人头顶血条、左上角主角血条，详见「表现与特效」。
- **模拟是确定性的**：逻辑以固定 1/60 秒一帧推进，随机数来自存在世界状态里的带种子随机数生成器。
  向量长度用 `Math.sqrt(a * a + b * b)`（`combat.js` 的 `magnitude`），不用各引擎近似结果不同的 `Math.hypot`。

## 不是真的 / 没做的

- 主角有新画的动作帧，但每个动作只有 1–6 帧，中间靠程序化的压缩、残影和刀光补；敌人仍然每种只有一张插画，动作全靠程序化（位移、挤压拉伸、前倾后仰、翻转、外发光、溶解）。
- 特效全部是 Canvas 2D 程序绘制，没有特效贴图或序列帧。
- 背景只有一张手绘场景图，镜像平铺；墙和地面画在同一张图里，所以墙没有单独的视差。
- 只做了妖塔一层一个样例关卡（三波）；其余 18 章、同伴、灵宠、装备与功法对动作战斗的影响、逃跑和自动战斗都没有做。
- 没有接入领域层：伤害、战意、掉落和结算都是原型自己算的，胜负不产生任何奖励。

### 约定

- **输入结构**（模拟层只看它）：`{ moveX, moveZ（-1..1）, attack, dodge, skill, spell, item（本帧按下的边沿）, attackHeld }`。
  `moveX` / `moveZ` 进入模拟时先截到 -1..1，再取整到 1/16 步（`world.js` 的 `STICK_STEPS` / `stickSteps()`），然后才做长度上限，
  所以实时操作和按步数记录的输入回放看到的摇杆值完全相同。
  各操作方案只是产出它的方式不同，都实现同一组接口：`create(container, { layout, getWorld })`，返回
  `read()`（每个模拟帧调用一次，取出本帧边沿后清空）、`setLayout(layout)`、`render(world)`、`handleEvents(events, world)`、`reset()`、`destroy()`。
  `main.js` 的 `SCHEMES` 表里登记新方案及其 `assist`。`layout` 是渲染器的屏幕分带（`W`、`H`、`hudH`、`bandTop`、`bandBottom`）加上 `safe`（逻辑 px 的四边安全区）。
- **事件只取一次**：`main.js` 每帧把 `world.events` 取空一次，依次交给 vfx、HUD、当前操作方案（按钮抖动），并记进 `window.__action.events`。
- **坐标**：`x` 沿舞台，`z` 是纵深（0 = 远 / 上沿，200 = 近 / 下沿），`y` 是离地高度（击飞用）；1 单位 = 390 宽屏幕上的 1 逻辑 px，
  实体位置即脚点。投影 `(x, z, y) → 屏幕` 只在 `renderer.project()` 一处，精灵、阴影、预警、特效、调试层共用。
- **事件**（`world.events`，视图每帧取走，模拟层从不调用视图）：
  `waveStart`（`index`、`name`、`count`、`arena`）、`swing`、`hit`（`attackerId`、`targetId`、`team`、`move`、`x`、`z`、`y`、`damage`、`heavy`、`killed`、`dir`、`danger`）、
  `dodge`、`evade`（见切时带 `perfect: true`）、`telegraph`（`id`、`move`、`shape` 及形状字段、`duration`、`danger?`）、`strike`（同上）、`death`（`boss`）、
  `waveCleared`、`stageCleared`、`heroDown`；第二阶段新增：
  `focus`（`value`、`delta`、`reason`：`finisher` / `perfectDodge` / `perfectDodgeHeavy` / `heavyHit` / `skill` / `spell`）、
  `perfectDodge`（`x`、`z`、`heavy`、`attackerId`）、`skill`（战技起手：`x`、`z`、`dir`、`delay` 到判定的秒数、`x0..z1` 判定框）、
  `spell`（`x`、`z`、`dir`、`name`、`delay`）、`projectile`（生成：`id`、`team`、`name`、`x`、`z`、`y`、`dir`、`speed`、`radius`、`color`）、`projectileEnd`（飞到头消散）、
  `item`（开始服用：`what`、`name`、`duration`）、`heal`（`amount`、`left`）、`denied`（`what`：`skill` / `spell` / `item`，`reason`：`focus` / `cooldown` / `empty` / `full`）、
  `breakout`（妖鬼 / 小鬼硬直抗性脱身）、`stagger`（`duration`）、`staggerEnd`、`enrage`、`bossIntro`（`id`、`name`）、`go`（`x` 触发线、`index`、`repeat`）。每个事件都带 `tick`。
- **按字段绘制**：渲染器只读实体字段（`sprite`、`telegraph`、`afterimage`、`showHpBar`、`hurt`、`activeHit` 等）。
  `sprite` 不认识的实体（飞行道具：`kind: 'projectile'`、`team`、`radius`、`color`）画成发光球，所以新增实体类型不用改渲染器。
  - 预警：`telegraph = { shape: 'ellipse', cx, cz, rx, rz, progress, duration, danger? }` 或 `{ shape: 'rect', x0, x1, z0, z1, progress, duration, danger? }`；
    `danger: 'heavy'` 是可见切的蓄力重击。判定形状就是画出来的形状（冲刺 / 扑击的判定是矩形里已经扫过的部分，飞行道具扫过的范围正好是矩形）。
  - 敌人当前招式：`move = { id, label, shape, windup, active, recovery, danger, hitsLeft }`（每次出手的实际蓄力时长；类型表里的 `attack` 只是主招的默认值）。
  - 主角：`focus` / `focusMax`、`spellCooldown`、`itemCooldown`、`items.pill`、`dodgeCooldown`、`empowered`（见切后加伤剩余秒数）；状态多了 `skill`、`spell`、`item`。
  - 首领：`boss`、`name`、`hp` / `maxHp`、`poise` / `maxPoise`、`staggered`、`enraged`；头顶血条关闭（`showHpBar: false`），由 HUD 画首领血条。
  - 世界：`arena`（锁场时 `{ left, right }`，否则 `null`）、`advance`、`combo = { count, timer }`、`slowMo`、`waveIndex`、`stage.waves`。
- **扩展点**：`stage.js` 的波次写 `triggerX`、`arena`、每个出生点的 `delay` / `boss`；`enemies.js` 的类型表按 `ai`（`melee` / `ranged` / `boss`）分 AI，
  招式统一走「蓄力 → 判定 → 收招」流水线，`shape` 可选 `ellipse` / `dash` / `shot`，`hits` 可做连段。

### 调试接口

`window.__action = { world, config, options, scheme, events, layout(), pause(), resume(), step(n), setInput(partial), setScheme(name), restart() }`

- `world` 是 getter，重开后指向新的世界。
- `scheme` 是当前操作方案名（`dual` / `onehand`）；`setScheme(name)` 和演示栏切换一样（换按键、换 `assist`、重开、写回 URL）。
- `events` 是最近 200 个模拟事件（旧的在前，重开时清空），用来核对输入是否真的进了模拟层（例如找 `swing`、`skill`、`dodge`、`denied`）。
- `layout()` 返回按键和 HUD 当前使用的屏幕分带与安全区。
- `step(n)` 暂停时也能推进 n 个模拟帧，然后绘制一次。
- `setInput` 里移动和按住类字段会一直保持，`attack`、`dodge` 这类边沿只在下一帧生效一次。

## 缓存版本号

静态服务不发缓存头，浏览器会按启发式缓存，以前出现过用户看到旧原型的情况。所以页面加载的每个本地 URL
（模块之间的 import、css、图片）都带同一个 `?v=N`。改完文件后在本目录运行：

```
node tools/bump-version.mjs          # 全部 ?v=N → N+1
node tools/bump-version.mjs --check  # 只校验：缺 ?v= 或版本号不一致都会失败
```

扫描范围是 `index.html`、`style.css`、`src/**/*.js`，以及 `tests/`。测试和页面 import 同样的 `?v=` URL，否则 Node 会加载出第二份模块。
JS 里写资源路径时，必须写成以 `./` 或 `../` 开头的完整字符串字面量，工具才能检查到。

## 已知问题

- 跑步：8 帧其实是同一步画了两遍（`run_4`–`run_7` 复用 `run_0`–`run_3`），两条腿没有真正交替，近看是「同一只脚领先」。
  每步着地脚往后滑约 13%（为了步频），同一帧停留时脚随身体前移约 22 px 再跳回（逐帧精灵固有）；原画落地→下沉之间着地脚本身也有最多 4 px 的滑动。
  起伏压掉了一部分，仍有约 9 px（腾空帧往下压最多 3 px，落地帧不动）。
- 跑速从 210 提到 240 px/s（只为跑步观感），横穿 390 宽的屏幕约 1.6 秒；机器人难度仍在目标内，真人手感没有校。
- 剑画得比攻击框长：平斩剑尖在身前约 124 px，攻击框只到身前 76 px（加敌人受击框半宽约 93 px）。敌人通常站在 66 px 的前排站位上，不明显；离得远时可能看到剑扫过却没打中。
- 起手和收势帧的剑尖是在图上量的（写在代码里），换美术时要重新量，或请美术在这些帧上也标 `tip`。
- 难度只用机器人校过（见「测试」），还没有真人上手。首领 1800 HP 加半血以上减伤，真人打可能偏长；不闪避基本过不了首领波。
- 软碰撞只挤开站着的身体：被击飞 / 倒地 / 冲刺中的敌人仍会和主角重叠；首领冲锋会从主角身上冲过去（判定照常）。
- 小鬼被逼到场地角落时只会往纵深两侧溜，不会从主角身边绕过去，所以贴边很容易被压制。
- 法术在施放开始时就扣战意、进冷却，施法前被打断不返还。
- 渲染没有插值，120 Hz 屏幕上移动可能略有抖动。
- 三张敌人插画的原始朝向都按「朝左」处理（`sprites.js` 里的 `artFacing: -1`：妖鬼的爪、小鬼的头、塔卒的刀都朝左）。哪张看起来朝反了，把它改成 1。
- 剔骨塔卒很高（185 px），它头顶的「破绽」标记和 HUD 横幅的位置接近，横幅显示的那几秒会被挡住。
- 受击闪白和外发光按画面时间计算，开慢放（`?slowmo`）时同样会变慢。
- 单手方案的甩动阈值（70% 半径、180 毫秒）、双击间隔和自动攻击距离只在无头浏览器里试过，没有真机调校；双击固定朝背后闪避。
- 双手方案战意满时，攻击要等松手才出（为了区分短按和长按），平时没有这个延迟。
- 结算面板在倒下或清场后 0.9 秒（按模拟时间算）弹出；开着慢放时会相应变慢。
