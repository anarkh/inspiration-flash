# 轮回之门 · 单屏入场原型

本目录保留独立 HTML / CSS 交互原型；原型页不读写游戏状态。已确认的交互于 2026-10-12 接入 Cocos 游戏，见下方接入记录。

## 交互

- 所有副本以紧凑横向图片卡片排列，缩小封面与卡片高度，让主列表能同时显示更多副本。卡片只负责选择，卡片上不放「进入」按钮。
- 默认选中首个可进入副本。锁定副本也可选中查看真实解锁条件，但底部「进入」按钮不可用。
- 协议、回响摘要与唯一的「进入」按钮固定在面板最底部。点击「调整」向上展开同屏整备，默认收起，为副本列表保留空间。
- 三种回响在按钮下方只保留当前方向的一行说明，随选择切换，不展开详情卡片。
- 底部「进入」使用当前选择与整备，不跳配置页、不追加确认；仅切到原型演示结果，不会调用游戏命令。
- 包含 390×844 与 320×568 尺寸切换、关闭与返回原型。

## 数据与素材

`data.js` 来自当前 `@infinite-flow/core` 的 DUNGEON_ORDER / DUNGEONS / getCampaignGates(createInitialState())，封面路径来自 asset-manifest。十九章均有对应图片。

新档示例：战力167，妖塔一层可进入，其他章节锁定。推荐战力只是提示；下一章由完成并领取前一章主线解锁。该示例不代表浏览器现有测试局或用户进度。

新档标准探索 / 强攻回响 / 不接契约 / 不携带种子可直接入场。三种回响方向可在原型切换。首通前不可使用其他协议或路线契约，没有归档种子；这些入口当前只显示真实限制。Cocos 接入复用原协议、炼狱层级、路线和种子规则。

## 回响说明依据

提示依据 `packages/core/src/run-relics.ts` 的遗物定义、候选池与 `game.ts` 的领取逻辑：强攻偏输出和战斗收益，守御偏防御与恢复，寻路偏探索与节点收益。方向在入场时固定；它只决定本局回响遗物候选池，在奖励节点选中具体遗物后才生效，不会在点击方向时直接增加属性。通常最多 2 选 1，同方向装备导体激活后最多 3 选 1。

## 验收边界

原型验收覆盖图片加载、320/390 排版、紧凑列表的可视空间、默认选中首个可进入副本、卡片切换选择、锁定条件与禁用状态、底部统一进入、向上展开的同屏整备，以及原型返回。检查列表滚动到底后仍能选择末项，底部固定区域不遮挡内容。原型证据不代表 Cocos 或微信真机验收。

## Cocos 接入记录 · 2026-10-12

`InfiniteFlowInfoSheet` 与 `InfiniteFlowView` 已应用同页图文选择、底部统一入场和向上展开设置；表现层提供真实章节与封面元数据，App 复用资源租约加载 19 张封面，沿用原命令与门槛。

Creator 3.8.8 Web-Mobile 独立构建已实测：390×844 默认完整显示 6 张卡片，320×568 显示 4 张；三回响单行说明、锁定条件、滚动时底部固定、选择守御后直接进入妖塔一层均已验证。锁定原因较长时说明区向上扩展，入场按钮位置不变。构建、类型检查、表现层测试、sheet/race 定向回归通过。该结果仅为本地 Web-Mobile 验收，未发布或进行微信真机验收。
