# 战斗 v3 · 对阵布局 HTML 原型

从 `infinite-flow-wechat/` 启动静态服务（例如 `python3 -m http.server 8762`），打开
`http://127.0.0.1:8762/prototype/combat-v3/`。无需安装依赖。五种底部指令并排对比：
`http://127.0.0.1:8762/prototype/combat-v3/docks.html`（可切 390×844 / 320×568、局面、战意，只看底部或整屏）。

本目录是隔离的交互原型：不读游戏状态、不写存档、不调用正式命令。数值只用于观察界面反馈，
正式接入时一律读取领域层结算帧。规则、数值和存档都不变，只改战斗的布局、演出与指令样式。
现在的规则一场只有一个敌人；多敌场景只用来看布局能否容纳以后的多敌战斗。

URL 参数：`?layout=diagonal|vertical`（斜向对阵、上下对阵）、
`?scenario=elite|three|five|heavy|solo`（单个精英、三个敌人、五个敌人、重击预警、无队友）、
`?skin=gold|plates|wide|sheet|tabs`（五种底部指令）、`?focus=0..3`（开场战意，看战技状态）、`?slowmo`（全部演出放慢 4 倍，便于逐帧看特效）、
`?shot`（隐藏顶部演示栏，便于截图）。

## 用户要求（按轮次）

1. 技能指令平铺在最下面一排，不放右侧；怪物和我方要有分界；双方面对面。
2. 象棋只是思路，参考梦幻西游、大话西游手游竖屏版的战斗布局；下方指令按钮一起优化。
3. 中间的分界光缝不要；缩小模型，后面会考虑同时对战多个敌人；指令按钮多出几种样式，
   不用简单线条，用图片或符合游戏内容的样式。
4. 排兵布阵没问题；按钮样式和布局仍不满意，攻击特效也不够好。
5. 战斗特效满意；只剩底部按钮：太复杂、按钮过多，先出几版简化原型。
6. 几种方案样式差不多；保留四圆键，其他删除，再多出几种样式，可以参考其他游戏。
7. 还是不满意：保留金边圆键，其他六种（字印、动作条、水墨、符箓、铁铸、细环）删掉重做一批。
8. 第二批（技能卡牌、彩色胶囊、斜切红黑、宝石金托、八卦法阵、主神面板）太丑、不符合游戏整体设计；
   没必要一直围绕这几个按钮图片。

## 布局（演示栏切换）

| | 斜向对阵（默认） | 上下对阵 |
| --- | --- | --- |
| 敌方 | 左上阵地：前排三个沿「/」斜线排开，后排两个站在前排之间、再往后一步（略小） | 上方：前排三个一排，后排两个在它们之间靠后 |
| 我方 | 右下一排：主角背对镜头，同伴在左下、灵宠在右上，同样沿「/」斜线 | 下方一排：同伴、主角、灵宠 |

- 没有分界光缝；两边靠阵地位置自然分开。
- 人物缩小：敌人约为战场高度的 21%（精英再大 15%，后排小 12%），主角约 18%。390×844 下敌人约 140px、主角约 116px。
- 每个敌人头顶一块小名牌（名字、血条）；精英带 ◆。多敌时当前目标脚下一圈金光；直接点哪个敌人就打哪个。
- 意图气泡放在右侧中部的空处，显示当前目标的下一步。
- 回合数移到指令台顶部的战报行最前面（「第 N 回合」），战场顶部留给敌方后排；每回合开始仍有横幅掠过战场。

## 指令台：按游戏现有界面语言做（演示栏切换）

前两批是另起炉灶的按钮皮肤，和游戏其他界面不是一套。这一批只用游戏里已有的部件，不再用物品图做按钮：

- 框：切角铁框，照搬 `cocos/assets/scripts/ui/dark-ui.ts` 的 `paintDarkFrame`（2 单位边、内细线、上沿亮线、下沿暗线），
  配色取 `battle-scene.ts` 的指令板和 `ROOM_SHEET`；没有圆形外框。
- 图标：`paintDarkIcon` 的线描图标（剑、法印、行囊、盾、左箭头），原样转成 SVG。
- 主键：和房间弹窗的「战斗」一样是亮金底、深墨字、棕色小字说明。
- 推荐（重击前的防御）：和现在战斗指令一样，板子提亮并加一圈淡金光；出手期间全部变暗。
- 每个键有一行小字：法术、道具写「N 种可用」，防御写「减伤 / 可格挡」，攻击写「普攻」或「战意已满」，下面三个菱形是战意。
- 逃跑、自动、法术和道具列表也换成同样的切角铁框。

| 方案 | 排法 |
| --- | --- |
| 金边圆键（保留） | 第一版四圆键：物品图配金边 |
| 铁券四键 | 四块等宽铁框横排，图标在左，名字和小字在右；攻击亮金 |
| 主键加宽 | 法术、道具、防御是三块小方框（图标在上、名字在下），攻击加宽成主键，带说明和战意 |
| 底部弹窗 | 整个底部是和房间弹窗相同的面板，战报是面板标题行；上面三个键，下面一条通栏亮金「攻击」 |
| 分段签条 | 一整条铁框分四段，像行囊的分页签；攻击段点亮，推荐的那段单独加亮 |

五种都在 390×844 与 320×568 下检查过（常规、重击预警、战意满、出手中）：文字不溢出，不压战报行。

## 攻击特效

特效改为在一张发光粒子画布上叠加绘制（加色混合），不再是细线和圆圈：

- 普攻：冲刺时身后留下金色残影；命中时目标闪白、顿帧约 0.07 秒、镜头向命中点推近一下、
  敌人后仰歪斜；一道渐变发光的弯月刀光（内侧透明、外缘白亮、带拖尾细线）横扫过身体，
  命中点白光爆开、火花四溅、脚下冲击波一圈，伤害数字是金色渐变大字。
- 战技：两道交叉的弯月刀光、更大的冲击波、全屏金色闪光，顿帧更长，数字下方标「战技」。
- 术法：脚下符文阵转动，一颗带连续拖尾的光球沿弧线飞向目标，落点符文圈展开、青色粒子爆开。
- 雷火符：一道锯齿雷光从天而降，全屏闪光，火星飞溅、余烬上浮。
- 敌人反击：敌人带红色残影冲过来，三道红色撕裂刀光、红色暗角闪一下；防御时是金色六角护盾。
- 敌人被击倒：灰烬粒子散开上浮。

正式游戏里同样的效果可以用 Cocos 的发光贴图（`art-source/battle-fx/` 的特效图生成后）加缩放、淡出和叠加混合实现；
图到位之前先按这里的程序效果做。

## 一个回合的演出

1. 主角迈背面步伐冲到目标面前出手：刀光、火花、敌人闪白后仰、震屏、伤害数字弹出；随即转身跑回原位。
2. 同伴冲过去打同一个目标再退回；灵宠原地跳一下、飘出「助攻 +12%」。
3. 每个活着的敌人依次冲到主角面前反击再退回。防御时显示「格挡」。
4. 回合数加一，横幅「第 N 回合」。敌人被打倒时变暗化烟；全部打倒显示「胜利」。

自动开着时，每回合停顿约 0.7 秒后按推荐行动出手（重击预警时防御，否则攻击）。

## 已知差异与待定

- 同伴和灵宠只有正面四分之三立绘，没有背面，所以现在是侧身朝向敌人，而不是像主角一样背对镜头。
- 多敌战斗需要改规则（目标选择、多个敌人各自反击、奖励与捕获），这次原型只验证布局；
  正式做多敌之前要单独设计规则。
- 正式实现只改 Cocos 表现层（`battle-scene.ts` 与战斗特效），沿用已做好的冲上去打再跑回、
  敌人冲过来反击、自动战斗、点敌人攻击等逻辑，换成这里选定的布局和指令样式。

## 文件

- `index.html`：结构与语义按钮。
- `docks.html`：五种底部指令并排对比页。
- `style.css`：战场、名牌、战报行与小按钮、金边圆键与四种铁框排法、320×568 紧凑档、减少动态效果。
- `app.js`：两种阵型、游戏铁框与线描图标的移植（`frameSvg`、`glyphSvg`）、五种指令排法、发光粒子特效、
  隔离示例状态、回合演出、自动战斗与列表。
- `proof/`：两种阵型（单精英、五敌，390 与 320）；五种底部指令的截图 `skins-*`（重击预警且战意 2，390 与 320；
  战意满，390）；特效慢放截图（普攻、战技、术法飞行与命中、雷火符）。

素材全部复用正式 resources：房间底图、敌人全身图、主角行走图（帧表取自 `cocos/assets/scripts/ui/hero-walk-atlas.ts`）、
同伴与灵宠全身图、物品、遗物与装备图标、头像；不新增素材。
