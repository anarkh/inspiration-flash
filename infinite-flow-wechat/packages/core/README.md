# Infinite Flow platform-neutral core snapshot

This directory snapshots the runtime TypeScript domain, content, and rule modules from
`infinite-flow/src` at source commit
`2645f0232542684d27de1abc321bb26913320420` (2026-08-07).

## Snapshot scope

- Copied: 64 non-test runtime modules, including every `src/level-data/*.ts` module.
  `src/run-lantern.ts` is a snapshot-local addition (see below).
  `src/action-combat/` (the real-time action combat simulation, ported from
  `prototype/action-combat-v1/src/sim`, exported as `./action-combat`) is a snapshot-local addition;
  its tests run under `npm test` (`test/action-combat/`, golden traces regenerated by
  `scripts/generate-action-combat-golden.mjs`). `src/action-encounter.ts` (the mapping from a
  committed fight to that simulation, see below) is a snapshot-local addition too.
- Excluded: `src/main.ts`, `src/balance-sim.ts`, `src/action-input-guard.ts`, every
  `src/**/*.test.ts`, and non-TypeScript browser assets such as `src/styles.css`.
- `action-input-guard.ts` is browser input policy and is imported only by `main.ts` and
  its own test in the source project.

Source-level relative imports are preserved. The emit build appends `.js` only in
`dist/` so the package is valid Node/Cocos ESM. Public subpaths used by downstream
workspaces are listed explicitly in `package.json`; Creator 3.8.8 does not resolve
the Node-style `"./*"` export pattern. `src/index.ts`, this README, `tsconfig.json`,
and the verification scripts are snapshot-local additions.

## Intentional core-only divergence

The copied `src/game.ts` does not call `Math.random()`. Callers entering a mode that
needs a generated seed must provide `DungeonEntryOptions.seedSource`; explicit
`hiddenTaskSeed` and `infernoMapSeed` values continue to take precedence. The source
web project is unchanged.

A won encounter (victory, capture, or a beaten pursuer) restores 20% of the
final derived maximum HP, capped at that maximum, so wounds carry into later rooms.
A successful escape heals nothing. Defeat and retreat during combat end the run and
still restore the player's HP to the final derived maximum. Damage history, rewards,
and defeat settlement remain intact. This recovery is independent of ordinary
healing modifiers and is an intentional rule change from the source web project.

The basic art (`art`) spends 1 focus and needs at least 1 to be cast. On regular
turns it gains no focus, while attacks and guards still add 1. An intent that
recommends the art still adds its +2 after the cost, and one that marks it
dangerous still takes 1 more. This is an intentional rule change from the source
web project.

On a successful exit the pressure-tier bonus and the difficulty (imprint / inferno)
reward-point multiplier scale the whole run's reward points, the loot bag plus the
exit share, instead of the exit share alone. The performance multiplier
(damage taken, clear depth, captures) still applies to the exit share only. This is
an intentional rule change from the source web project.

Elite and boss encounters telegraph a `heavy-blow` intent on turns 2, 5, 8, ...
whenever no monster-specific intent applies: the counter deals 50% more, a guard keeps
only a quarter of it, and `performCombatAction(..., { timing: 'perfect' })` on that guard
halves the remainder and adds 1 focus. Ordinary encounters and every other turn keep the
source rules; the timing option is ignored wherever a perfect parry is impossible. This is
an intentional rule change from the source web project.

Weapons without a signature skill (the starter `training_blade` and eight others) no longer
leave full focus unusable: `getWeaponSkillStatus` falls back to the generic `charged_strike`
(蓄势斩), a physical hit for 1.8x the basic-attack formula that spends focus like any weapon
skill. Signature skills are unchanged. This is an intentional rule change from the source
web project.

Runs entered through the stage-2 flow on any chapter (standard or imprint protocol) carry
a `lanternState`, except the opening chapter's first clear (`isOpeningChapterFirstClear`),
which teaches fights and doors with neither lamp nor pursuer. The lamp comes from the new
`src/run-lantern.ts`: 12 drops of lamp oil, one burnt per
`moveToNode` into a room the lamp has not lit yet (lit and cleared rooms are free), four more
when one of the chapter's four supply rooms is cleared, and two more lost on a pursuer contact.
Such runs meet a dormant pursuer even on a first clear. A lamp never holds more than its start plus every supply refill (28 drops);
a snapshot above that is malformed. The burn that empties the lamp sets `breachForced` on the run's pressure
state, which `getRunPressureStatus` reads as breach whatever the cleared count, and wakes a
dormant pursuer at once. A pursuer now also makes contact when the player walks into its
room, even on its resting step. `getRouteForecasts` previews every adjacent room (kind,
a three-step risk read from the basic-attack exchange or the trap roll, reward bonus, oil,
boss fusion, the pursuer's approach and the containment room) without changing state. It
reads bonus, fusion and risk from the state that very step would leave, through the same
move effects `moveToNode` applies (burnt drop, forced breach, woken or colliding pursuer). Runs without a
lamp (older saves and deep runs) keep the source movement rules. These are intentional
rule changes from the source web project.

Fights can also be played as real-time action fights. A fight still starts through
`selectNode` or a pursuer contact with the same `CombatState`; `buildActionEncounter(state)`
derives the whole fight from that committed state alone (seeded by hashing run facts, so the
client, the view model and the reducer build the same one): the room's own monster three times
in a normal room (two with the ranged kit and one with the melee kit when that monster is a
shooter), the elite plus two of the chapter's normal monster (the first monster room's monster
that is neither its elite nor its boss) in an elite room, the boss plus two later adds in a boss
room, a caught pursuer alone. The hero carries the derived maximum and current HP, the fight's
focus, the healing pills usable in it (their heal after potency and field healing) and three-hit
combos that add up to the hero's best turn-based basic hit on the room's monster — the plain
attack or, while methods are not sealed, the art hit, since the turn-based fights are balanced
on that best hit; the spell is the turn-based art hit (sealed with methods), the skill the
equipped weapon's skill resolution (its heal included), and the law's outgoing force/art
percentages apply. Every enemy strike is the turn-based counter hit on the hero times a fixed
move ratio; members take the hero's damage scaled by their own defense relative to the room's
monster, measured with the same basic hit the combo stands for, and their HP is the fully scaled
monster HP times a per-kit factor. A sealed boss enrages at half HP into its awakened phase's
damage dealt and taken; elites and pursuers fight with the boss kit without enrage.
The tables, melee / ranged assignment and calibration live in `src/action-encounter.ts`
(`ACTION_ENCOUNTER_TUNING`, `ACTION_MONSTER_KITS`; `scripts/balance/action-calibrate.ts`). The
spell's strength (a piercing art hit, often stronger than a whole combo late in the campaign) is
a known tuning item pending human play: the scripted bots that calibrated these fights rarely
cast it.
`resolveActionCombat(state, log, capturePetId?)` replays the whole fight's input log (at most
ten minutes) on that encounter and settles it through the turn-based end-of-fight paths: the
first direct action as the opening signal (attack, spell = art, skill by its damage kind,
dodge = guard; on 战痕复演 take rooms it also records the take with that opening's turn-based
value), spent pills consumed and recorded, the fight's final HP with the HP it took added to the
run's damage, the boss awakening when the sealed boss enraged, then the normal victory, defeat
settlement or — for a log that ends mid-fight with a capture — the normal capture once the
replayed room monster is under the capture line. A log that ends mid-fight without a capture is
rejected, and mid-fight progress is never saved: a reload restarts the fight from its committed
start. Escape stays the turn-based action, so a failed escape takes its counterattack and the
fight restarts from the new state. Not mapped in this version (generic kit behaviour instead):
the monster-specific combat effects and intents, the heavy-blow parry (the sim's perfect dodge
plays that role), companion and pet strikes and support, bloodline hit effects, equipment
keywords other than potency, the armour-piercing sword and cloud-step bonuses, iron-body and
armour-patch guards, the thunder talisman and other combat items, method techniques, soul skills,
equipment-memory focus storage, and per-hit law hooks: 零和审计官's collection seals and
无名镜王's mirror shells are neither consumed nor halve its damage, and 战痕复演's sequence /
afterbeat replay releases, replay buffer and the awakened director's repeat penalty are skipped
(releases that happen when the fight opens still lower the room monster's starting HP). These
are intentional rule changes from the source web project; the turn-based actions are unchanged.

The two `Array.prototype.at()` reads in copied `src/dungeon-laws.ts` use equivalent
length-indexed access so the same rules compile against the WeChat/Cocos ES2020
library surface. This changes neither ordering nor fallback behavior.

The compiler configuration intentionally omits DOM libraries and ambient type
packages. From `infinite-flow-wechat/`, validate with its pinned workspace tools:

```sh
npm run build -w @infinite-flow/core
npm run typecheck -w @infinite-flow/core
npm test -w @infinite-flow/core
```
